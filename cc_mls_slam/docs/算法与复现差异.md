# FAST-LIO2 + M-detector + 静态点云 PGO 融合基线

这是根据用户提供的两个源码压缩包和 CC-MLS 论文组装的研究源码基线。原始压缩包和桌面源码未修改。**已完成源码接入及静态检查；未在 ROS/Linux 下编译、运行或回放，因此目前不能称为已经验证可运行的版本，也不能宣称复现了论文实验精度或实时性能。**

## 代码与流程

```text
LiDAR + IMU
    ↓ 时间同步、IMU 传播、点云去畸变（每帧一次）
保存传播状态 x_prior 和协方差 P_prior
    ↓
全点第一遍 FAST-LIO2 更新 → 暂定位姿
    ↓
动态检测 → M-detector 稀疏体素聚类 → 静态点 / 动态点
    ↓
恢复 x_prior 和 P_prior，重建静态点的匹配缓存
    ↓
静态点第二遍 FAST-LIO2 更新 → 最终位姿
    ↓
静态点更新 ikd-Tree；最终位姿提交历史深度图
    ↓
静态关键帧 → Scan Context → GICP 回环验证
                    + 共视边 → iSAM2 → 优化轨迹、地图
```

`FAST-LIO/src/laserMapping.cpp` 是融合入口。动态模块在同一帧内直接调用，不再通过独立 M-detector 节点按队列数量配对里程计。

`M-detector` 编译为共享库 `m_detector_core`。其历史点数组按帧持有，根据仍被历史图和延迟队列引用的最早时间释放，避免原来的固定环槽提前覆盖。检测与提交历史分离，以第二遍最终位姿构图。

`cc_mls_backend` 复用 SC-PGO 中的 Scan Context 实现，使用新的单线程回调管理关键帧、GICP 和图优化。输入为严格同时间戳的 `/fusion/static_lidar` 与 `/fusion/lidar_odometry`，两者都对应 LiDAR 坐标系，已在前端组合 LiDAR–IMU 外参。原 `SC-PGO` 保留为参考，通过 CATKIN_IGNORE 排除构建，未使用其存在共享数据竞争的多线程节点。

动态检测有两种可切换模式：

- `dyn_obj/paper_depth: true`：四通道深度区间、2×2 汇聚、五帧多数投票和径向速度阈值传播，依据论文第3.4节实现。
- `dyn_obj/paper_depth: false`：原 M-detector 的 Case1/2/3 检测，用于融合与消融基线。

两种模式均可使用原 M-detector 聚类。当前采用稀疏体素、串行确定的框处理、逐轴范围检查和迭代连通搜索，优先排除内存与并发问题。

## 与论文的对应及差异

| 论文部分 | 当前基线 | 需要注意 |
|---|---|---|
| 两遍 LIO，共享 IMU 预测 | 已实现 | 两遍均从同一个状态和协方差先验启动；IMU 去畸变只运行一次 |
| 静态点第二遍更新及地图插入 | 已实现 | 静态几何不足时保留 IMU 预测，不插入地图，也不给后端提交关键帧 |
| 四通道历史深度、2×2 汇聚、时间投票 | 已实现 | 用角度分辨率定义球面图，而非直接用传感器线数 H；每历史帧对每查询点最多贡献一票，避免同像素多点重复累计 |
| 接近/远离的速度约束 | 已实现基本公式 | 明确按历史时间正序传播正速度幅值；速度初值0.5m/s，深度容差0.15m，是可配置工程设定，论文未给出完整参数规则 |
| 每帧历史深度 | 默认0.1s一张图，5张图 | 针对10Hz。换帧率要同时改frame_dur和depth_map_dur，避免多帧被合并进同一张图 |
| 0.3m体素、地面与物体补全、70%置信度 | 复用并修正原M-detector聚类 | **未完全复刻论文第3.4.4节的“世界竖直方向仅向下两层、xy足迹不变”的窄带采样和区域生长**；当前仍为原库的框周围扩展及平面判据 |
| 2m/10°关键帧、静态Scan Context、GICP、Cauchy | 已实现 | 回环几何验证使用单历史关键帧，不是多帧子图；仍需实测调参 |
| 短程共视边 | 已实现候选重叠筛选和里程计相对位姿边 | 重叠采用双向最近邻比例的较小值；阈值和固定噪声属工程配置。共视边与里程计边相关，当前近似不能解释为新增独立几何观测 |
| 从起始构建纯静态地图 | 部分实现 | 无历史时不能判断运动，原始启动地图仍含未经确认的点。前几帧也可能因投票不足保留动态点；本版不回溯清除已经插入的历史动态点 |
| 全局优化进一步提升去动态 | 后端使用静态观测优化轨迹 | 本版不会把PGO历史位姿变化反馈到前端深度窗口，也不会自动重新运行历史过滤 |

因此它是明确可审查的融合复现基线，不是作者 CC-MLS 官方代码，也不是完整论文实验复现。论文定义的 PR/RR 调和指标亦不等于常规动态分类 precision/recall 的 F1，评估时须分别报告。


## 单包目录对应

本文件前半部分描述的是原三包版算法，后续单包版已统一四种动态标签，按方向分别投票，详见四种动态运动类别.md；主干流程保持一致。路径对应：

- FAST-LIO/src → src/lio
- M-detector/src → src/dynamic
- cc_mls_backend/src → src/backend
- 所有公开头文件 → include
- 包名统一为cc_mls_slam，启动统一为launch/mapping_ouster128.launch、mapping_horizon.launch、mapping_hap.launch

实际构建、运行和依赖安装方式以根目录README.md为准。
