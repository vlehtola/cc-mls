# 新电脑安装与依赖审查

本版以 Ubuntu 20.04、ROS 1 Noetic、GCC 9/C++17 为安装目标。它是 catkin/ROS 1 包，不能直接放进 Ubuntu 22.04/24.04 的 ROS 2 工作区。ROS Noetic 已于2025年5月31日结束官方支持；新机需先准备可用的 Noetic 环境，发行包下载可用性取决于所用软件源。本次没有在Linux新机上执行安装，不承诺已实测通过。

## 依赖对应

| 依赖 | 用途 | 安装来源 |
|---|---|---|
| ROS Noetic / catkin / 消息生成 | 构建、消息、前后端通信 | 已配置的ROS软件源 |
| PCL / Eigen / Boost | 点云、矩阵、上游头文件及驱动 | libpcl-dev / libeigen3-dev / libboost-all-dev |
| OpenCV | M-detector深度与聚类相关代码 | libopencv-dev |
| TBB | C++17并行算法的运行库 | libtbb-dev，保留系统包，不硬编码.so路径 |
| OpenMP / pthread | 并行处理与ikd-Tree | GCC的OpenMP运行库、系统线程库；CMake检测 |
| GTSAM 4.2 | 回访、共视因子及iSAM2 | 官方4.2标签源码，使用系统Eigen |
| Livox SDK（旧版） | 旧版Livox驱动构建 | Livox-SDK官方源码 |
| livox_ros_driver（旧版） | CustomMsg及Horizon数据输入 | 官方旧版驱动源码 |
| APR | 旧版Livox驱动构建检测 | libapr1-dev |
| RViz | 三个launch默认可视化 | ros-noetic-rviz |
| gtest / rostest | 核心验证 | libgtest-dev / ros-noetic-rostest |

本包不需要Ceres、Python.h或matplotlib。Python3仅用于ROS构建/rosdep工具。include/matplotlibcpp.h为未被当前构建使用的上游遗留文件，不需要为它安装Python开发库。ikd-Tree、IKFoM、Scan Context和聚类头文件已包含在包内，无需另外安装三个SLAM项目。

旧版Livox消息仍是构建依赖，即使只使用Ouster也需要。HAP已支持ROS1 driver2的PointCloud2（xfer_format=0），无需旧CustomMsg转换；下方安装脚本不安装driver2/SDK2或Ouster设备驱动，实机使用前按各自官方文档安装。同步IMU仍是必要输入。回放兼容rosbag时不一定需要启动设备驱动；连接实机需另外安装相应官方驱动。

## 安装

1. 在新电脑准备Ubuntu20.04与ROS Noetic，确认 `/opt/ros/noetic/setup.bash` 存在。ROS安装入口见下方官方参考；脚本不会自动改ROS软件源。
2. 将压缩包中cc_mls_slam目录解压到 `~/catkin_ws/src/cc_mls_slam`。建议使用新工作区，避免旧版fast_lio、m_detector等同名源码混入。
3. 在普通用户终端运行（脚本内部仅系统安装使用sudo）：

```bash
cd ~/catkin_ws
bash src/cc_mls_slam/scripts/install_new_machine.sh "$PWD"
bash src/cc_mls_slam/scripts/verify_installation.sh "$PWD"
```

脚本先安装系统包，再安装Livox SDK和GTSAM，然后拉取旧版Livox ROS驱动并整体构建工作区。默认并行数2，内存较少时用 `BUILD_JOBS=1 bash ...`。依赖源码放在工作区 `.cc_mls_dependencies`，不会被catkin当作ROS包扫描；旧版Livox驱动作为外部ROS包位于src。已有依赖目录不会被删除或切换版本；不符预期时脚本失败并提示检查。

GTSAM固定4.2标签；Livox SDK/驱动使用安装时的master，并记录实际commit到 `.cc_mls_dependencies/installed_versions.txt`，因此不是离线锁定依赖包。保存该文件及相应依赖源码后可以固定同一版本迁移。整个流程需要网络与可用的软件源，不能称为离线安装包。已存在其他GTSAM安装时应检查CMake选择的GTSAM_DIR，避免混用不同Eigen或不同版本库。

`gtsam`暂时没有base rosdep规则，脚本在完成源码安装后才使用 `--skip-keys gtsam`。Noetic已EOL，`rosdep update`使用 `--include-eol-distros`。不要将跳过规则误认为不需要GTSAM。

## 安装后启动

```bash
source ~/catkin_ws/install/setup.bash
roslaunch cc_mls_slam mapping_ouster128.launch
# 或 mapping_horizon.launch；HAP使用driver2的xfer_format=0后启动mapping_hap.launch。
```

三份传感器配置中的外参是占位值，使用前必须修改。前端输出目录改为运行时创建，默认 `${ROS_HOME:-$HOME/.ros}/cc_mls_slam/run_<时间戳>`，不再依赖原电脑或构建源码路径。可用全局ROS参数 `output_directory` 指定可写目录，例如启动前执行 `rosparam set /output_directory /absolute/path/to/frontend-results`；重复指定同一目录会覆盖同名日志，建议每次使用新目录。后端结果继续由launch的save_directory控制。

## 本次修正及验证边界

- 增加经典TBB包的CMake查找回退，避免依赖TBBConfig.cmake或固定libtbb.so路径。
- 显式链接Eigen3::Eigen，要求GTSAM4.2导出gtsam目标，安装脚本让GTSAM使用系统Eigen。
- 补充PCL、Boost、RViz和gtest依赖声明，保留消息生成与旧版Livox驱动依赖。
- 增加ROS导出目标的构建顺序依赖。
- 删除编译时ROOT_DIR路径，创建可写运行目录，并检查FILE日志打开失败。
- 提供整体安装脚本及安装验证脚本，验证install空间、动态库、launch解析和核心测试。

当前只执行源码、路径、XML和压缩包检查，两个Linux脚本尚未运行。新电脑上第二个脚本通过后，才可以声称该电脑安装/编译与测试通过；它仍不能替代真实数据回放与三类传感器验证。
