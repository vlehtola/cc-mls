# 运行问题修复记录（2026-09-15）

本轮在上一轮编译阻断、空帧同步、数组越界修复的基础上，继续处理剩余运行问题。以下是当前源码行为；Linux编译、测试执行和实机验证尚未完成。

## 输入兼容

- HAP现在使用 `preprocess/lidar_type: 4`，直接订阅ROS1版livox_ros_driver2的PointCloud2，驱动设置 `xfer_format=0`。读取x/y/z/intensity/tag/line/timestamp，无需将CustomMsg转换成旧驱动消息。
- 官方driver2当前的PointCloud2把 `timestamp` 写为相对扫描起点的纳秒偏移，默认 `point_time_scale_ms=1e-6`；不是绝对Unix时间。依据[官方lddc.cpp](https://github.com/Livox-SDK/livox_ros_driver2/blob/master/src/lddc.cpp)的InitPointcloud2Msg实现。设备驱动仍须单独安装，参见[官方安装说明](https://github.com/Livox-SDK/livox_ros_driver2)。本包不新增driver2编译依赖，旧版Livox依赖仍用于Horizon和旧CustomMsg支持。
- Ouster按字段解析，支持UINT8/UINT16等数值类型的ring、组织化点云行填充和不同字节序，不再要求固定PCL结构。默认时间字段为t、相对纳秒；不同格式须明确设置point_time_field/point_time_scale_ms，缺字段仍报错，不猜测时间单位。
- 新解析器检查数据长度、行宽、点步长、字段偏移和类型，避免越界与未对齐读取；检查点时间范围，排序后交给去畸变。
- HAP/Ouster默认路径要求feature_extract_enable=false。HAP的scan_line=128是line ID接收上限，不是物理线数。两者max_scan_points默认600000；超过上限会拒绝该帧。

## 启动地图与输出

新增fusion/rebuild_map_after_warmup，默认true。历史窗口填满且静态第二遍更新成功后，通过ikd-Tree的删除/插入接口，把临时启动地图替换为当前静态观测，避免未经确认的启动点永久留在地图中。

完成替换之前，不向回环后端发布静态关键帧，不累积PCD保存点。替换帧后的下一有效帧开始给后端发送静态点。替换会舍弃启动期未被当前帧覆盖的几何，这是保守的初始化处理；不能据此保证每个动态点都能被识别，也不能消除启动位姿已经产生的误差。

## 内存和积压

| 参数 | 默认值 | 达到限制时 |
|---|---|---|
| queues/max_lidar_frames | 20 | 内部LiDAR队列达到上限，报错并停止当前SLAM |
| queues/max_imu_samples | 4000 | 内部IMU队列达到上限，报错并停止当前SLAM |
| publish/max_path_poses | 10000 | 前端可视化轨迹只保留最近点；不影响滤波 |
| pcd/max_chunk_points | 2000000 | 下次追加前将已有点写入chunk_N.pcd；末尾剩余写scans.pcd |
| dyn_obj/history_point_memory_mb | 2048 | 在点历史数组分配前拒绝超预算帧；前端重置检测历史并跳过该帧地图更新 |
| /cc_mls_backend/max_keyframes | 5000 | 保存已配置的轨迹后，报错停止整套required launch |
| /cc_mls_backend/max_stored_scan_points | 20000000 | 同上，限制后端存储的关键帧点总量 |

中间件订阅/发布队列也已缩小。ROS传输层仍可能因处理过慢丢消息；停止策略不会自动恢复、分段拼接或保证不丢包。历史点内存预算不包含深度图、PCL临时对象、图优化分解内存等，不能当作整个进程的内存上限。PCD内存受分块阈值加单帧点数约束。

这些是容量保护，不是无限时长SLAM或图边缘化实现。队列达到上限应先检查LiDAR/IMU是否同时输入及回放倍率；不要无依据放大限制。后端未设置save_directory时不会自动保存轨迹文件，应在长序列采集前配置。

## 其他修正

Odometry的协方差改为先写入再发布，避免发布上一帧协方差。Livox关闭特征提取时不再为所有线预留整帧容量，降低无用内存占用。ros::shutdown之后，主循环立即停止处理缓存帧。
