# 全库安装环境与运行审查

审查对象：当前单包cc_mls_slam，以及用户提供的M-detector-main.zip、FAST_LIO_SLAM-main.zip原始README/CMake。这里FAST_LIO_SLAM是FAST-LIO2 + SC-PGO，不是另一份独立FAST-LIO-SAM或LIO-SAM仓库；未提供的仓库不能视为已核验。

结论：新包沿用两库共同的ROS1/C++17基础，但不是原始构建文件的原样复制。Ubuntu20.04 + Noetic + GCC9符合原README的基础版本要求；不代表该组合已经在本次环境中编译成功。本轮找到确定的编译阻断与运行错误并修复，仍有数据适配、资源规模和论文复现差异，不能称为无bug版本。

## 原始环境对照

| 项目 | 原始文件要求 | 当前单包 |

## 仍然存在的限制与待验证风险

1. **HAP未完成driver2消息适配。** 仅安装依赖或加载hap.yaml不能让旧版CustomMsg订阅接收driver2消息。
2. **Ouster输入结构有限制。** 当前要求FLOAT32 x/y/z/intensity、UINT32 t（纳秒）、UINT8 ring。其他驱动版本可能发布不同结构，需要转换或增加处理器。拒绝不匹配消息是保护，不等于已适配所有Ouster128设备。
3. **时间语义仍依赖驱动。** LiDAR header应为扫描起点，点时间为相对此起点的非负偏移；按最大偏移修正扫描结束并不能修正设备时钟偏差。不能靠time_sync_en替代正确硬件同步。
4. **原始启动地图并非确认静态地图。** 历史窗口不足时可能插入动态点，本版不回溯清除；这是算法缺口，修补安装依赖无法解决。
5. **内存和实时性未测。** 动态模块每点含多帧投影缓存，五帧高密度点云可能占用大量内存；600000是输入保护上限，不是实时性能保证。更大多回波/高分辨率模式需调上限与内存预算；增加buffer_delay时队列还需容纳多帧。
6. **长序列后端增长。** 关键帧、描述子、位姿图和完整路径持续增长，地图发布点数上限不限制关键帧存储。单线程GICP也可能积压订阅消息；尚未实现分块归档和后端回压。
7. **前端消息队列资源。** IMU/点云长期缺失一侧或处理速度不足时，队列仍可能积压；没有完整的有界队列与掉帧重同步策略。
8. **论文实现并未完全一致。** 聚类窄带采样、共视边噪声、启动清图与PGO回馈仍见算法差异文档。四个动态名称中的进入/离开属于按深度偏差的工程标签。
9. **继承功能验证范围。** 本轮以三个launch默认路径为主；非默认特征提取、旧M-detector消融、Velodyne遗留路径及所有参数组合没有逐项运行验证。
